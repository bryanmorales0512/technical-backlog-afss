SimPRO API Calls
Step 1 — Job List
GET /companies/{id}/jobs/
Pages 1–10 fetched in parallel. Filtered to CFSP tech ID 1126. Returns up to 2,500 jobs per company/stage.
Step 2 — Job Details (per job, concurrency 10)
GET /companies/{id}/jobs/{jobId}
Full job object — labour hours, status name, all enrichment fields.
Step 3 — Schedules (per job, concurrency 10)
GET /companies/{id}/schedules/?JobID={id}
Confirmed booking date and total scheduled hours per job.
Step 4 — Sites (per unique site, concurrency 10)
GET /companies/{id}/sites/{siteId}
Site name and address. Deduplicated — each unique site fetched once.
Step 5 — Customers (per unique customer, concurrency 10)
GET /companies/{id}/customers/{segment}/{id}
Customer profile and group name. Deduplicated across all jobs.
Rate Limiting

Steps 2–5 run in parallel streams, up to 40 concurrent API calls. SimPRO enforces HTTP 429 limits — each call retries up to 8× with exponential backoff (1s → 2s → 4s → 8s…).

Dashboard Fetch Pattern

The dashboard fires 7 parallel fetches on load:

Parallel Requests on Page Load
  • Company 1 Pending — RM AFSS pending jobs
  • Company 1 Progress — RM AFSS in-progress jobs
  • Company 8 Pending — CHUBB/AFAC pending jobs
  • Company 8 Progress — CHUBB/AFAC in-progress jobs
  • Company 10 Pending — AE Evac pending jobs
  • Company 10 Progress — AE Evac in-progress jobs

Each response renders immediately as it arrives — the table updates company-by-company rather than waiting for all 7. /api/tech-support loads independently in the bottom section.

Cloud Scheduler

Google Cloud Scheduler hits /api/warmup every 30 minutes automatically, keeping caches populated before users ever request data.

CFSP Job Filter

Only jobs with technician ID 1126 ("A CFSP ONLY") assigned appear on the dashboard — except Company 8 (CHUBB/AFAC) which shows all jobs.

Month Filter Effect

When a month is selected (top-right dropdown), only jobs whose scheduled date falls in that month are counted in status rows. The Total Backlog row always shows all jobs regardless of filter.

Mixed Plan Type Exclusion

If a Completed job has another "A …" plan-type technician alongside "A CFSP ONLY" (e.g. "A Hydrant"), it is excluded from the Complete row to avoid double-counting across dashboards.

Cold Cache Trigger

A cold cache occurs when Cloud Run recycles the container — new deployment, idle scale-down, or instance restart wipes /tmp. The Cloud Scheduler warmup job prevents users from ever hitting cold cache under normal operation.

Partial Flag

Each cache file stores a partial: true/false flag alongside the data. A fresh but partial cache means enrichment was incomplete on the last write — it's still served immediately but triggers background re-enrichment.

Workflow 5 — Automatic Cache Warmup
1
Cloud Scheduler fires every 30 minutes
Job: afss-warmup-job — schedule */30 * * * * UTC. Sends GET request to /api/warmup.
2
warmup route runs all three warmers in parallel
warmAll() + warmLeave() + warmTechSupport() run simultaneously.
3
warmAll() processes 6 combos sequentially
Company 1 Pending → Company 1 Progress → Company 8 Pending → Company 8 Progress → Company 10 Pending → Company 10 Progress. Sequential to avoid SimPRO 429 rate limits.
4
Each combo runs full fetchAndCache()
Job list → 4 parallel enrichment streams → write to /tmp/afss-jobs-{co}-{stage}.json with partial: false.
5
Warmup returns success report
Returns {"ok": true, "results": [{company, stage, ok, ms}, ...]}. All subsequent user requests served from fresh cache instantly.
Why Sequential for Jobs?

Running all 6 company/stage combos in parallel would fire 240+ simultaneous SimPRO API calls, causing severe rate limiting (many 429s) and actually increasing total time. Sequential keeps it to ~40 concurrent calls at a time.

Post-Deployment Warmup

Every new deployment creates a fresh container with empty /tmp. The following command must be run after each deploy to pre-populate all caches before users arrive:

# PowerShell — run after gcloud deploy
Invoke-WebRequest `
  -Uri "https://bryan-technical-afss-712513641417
  .australia-southeast1.run.app/api/warmup" `
  -TimeoutSec 310
Warmup Duration

Full warmup takes 2–5 minutes depending on SimPRO API speed. Company 1 Pending (85 jobs) and Company 10 Progress (123 jobs) are the slowest, taking 45–160 s each. All other combos complete in under 20 s.
